## 3. Audit sécurité

### Vulnérabilités corrigées dans ce PR

| # | Sévérité | Fichier | Description | Correctif |
|---|---|---|---|---|
| S1 | **CRITIQUE** | `app/core/config.py:11` | `SECRET_KEY` avec valeur par défaut `change-me-in-production-...`. Permettait à n'importe qui connaissant cette constante de forger des JWT en prod. | Refus de démarrer en prod si la clé est absente ou égale au sentinel. En dev, génération d'une clé aléatoire éphémère + warning. |
| S2 | **HAUTE** | `app/api/admin/router.py:194` (ancien) | L'endpoint `/admin/create-tables` utilisait `SECRET_KEY` comme bearer admin → divulgation de la clé JWT = bypass total. | Remplacé par `ADMIN_BOOTSTRAP_KEY`, comparaison constante (`hmac.compare_digest`), refus si non configuré. |
| S3 | **HAUTE** | `app/api/auth/router.py` | Aucune limitation de débit sur `/auth/login` → bruteforce trivial. | Nouveau `app/core/rate_limit.py` : 10 tentatives / 5 min / IP, 429 + `Retry-After`. Reset au login réussi. |
| S4 | **HAUTE** | `app/api/crm/router.py:24` & `:646` | Endpoints publics `lookup` et `personal-shopper` divulguaient l'existence d'un email. | Validation format email, message générique "Aucun compte trouvé". TODO long terme : passer à un flux magic-link (cf. §7). |
| S5 | **MOYENNE** | `app/api/pos/router.py:274,294` & `app/api/crm/router.py:498,545` | `except Exception as e: raise HTTPException(detail=str(e))` exposait stack traces SMTP / Twilio aux clients. | `logger.exception(...)` côté serveur + détail générique côté client (502 "Réessayez plus tard"). |
| S6 | **MOYENNE** | `app/main.py:108` | Le handler global d'exceptions renvoyait `type(exc).__name__: str(exc)` → divulgation d'info en prod. | Détail masqué si `ENVIRONMENT=production`, conservé en dev pour debug. Ajout `request_id` dans la réponse pour corrélation. |
| S7 | **MOYENNE** | (transverse) | Aucun en-tête de sécurité HTTP. | Nouveau `SecurityHeadersMiddleware` : `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy`. |

### Reste à traiter (cf. §7 plan de correction)

- **S8** : `/api/crm/clients/lookup` reste accessible sans auth. La vraie correction nécessite un magic-link OTP envoyé par email — c'est un changement fonctionnel qui sort du périmètre de cet audit.
- **S9** : `/admin/seed` insère un mot de passe en clair `vintiz2026`. Doit imposer un changement de mot de passe au premier login.
- **S10** : Le rate-limiter actuel est mémoire-process. En multi-worker (gunicorn -w 4), il devient inefficace. Migrer vers Redis (préfixe `ratelimit:`).
- **S11** : Pas de CSP (Content-Security-Policy) sur l'admin Next.js. À ajouter via `next.config.mjs`.
- **S12** : Aucune rotation de JWT (`refresh` régénère mais ne révoque pas l'ancien). Acceptable tant qu'on ne stocke pas le token dans un cookie réutilisable.

### Nouveautés livrées

- **`app/core/logging_config.py`** : `setup_logging()` configurable via `LOG_LEVEL` et `LOG_JSON`. Format JSON pour shipping vers Loki / Datadog en prod, format texte coloré en dev. Tame des loggers tiers (sqlalchemy, uvicorn.access).
- **`app/core/middleware.py`** :
  - `RequestIdMiddleware` : génère / propage `X-Request-ID`, expose `request.state.request_id`, log structuré de chaque requête (`method`, `path`, `status_code`, `duration_ms`).
  - `SecurityHeadersMiddleware` : voir §3.S7.
- **Logs métier** : `auth.login` (succès et échec avec IP), `pos.resend_email/sms`, `crm.send_email/sms`, `crm.welcome_campaign`, `weather` ont tous `logger.info` ou `logger.exception` côté succès / échec.

### À brancher en prod (hors PR)

- Exporter les logs JSON vers Loki / Datadog / CloudWatch
- Sentry (FastAPI middleware + Next.js plugin) pour les exceptions non-gérées
- Métriques Prometheus (`prometheus-fastapi-instrumentator`) → CPU, latence p95, taux 5xx
